The challenge

Unexpected downtime creates pressure.

Hospitals rely on critical medical equipment. Unexpected faults can lead to urgent repairs, disrupted workflows, and extra maintenance effort. Scheduled maintenance is important, but condition changes can occur between inspections.

Our proposed solution

Make equipment condition easier to see.

MedSentry aims to bring selected sensor readings, simple abnormality checks, and maintenance alerts into one clear monitoring workflow.

〽️

Condition monitoring

Candidate vibration and temperature sensors collect readings from a suitable, non-clinical test setup.

📊

Clear status display

A planned dashboard will present readings and show when configured thresholds are exceeded.

🔔

Maintenance alerts

Warnings can prompt a trained person to inspect the equipment; an alert alone does not confirm a fault.

System workflow

From sensor readings to a maintenance prompt.

The initial prototype is planned around threshold-based abnormality alerts. Machine-learning-based failure prediction is a possible future enhancement after suitable data and validation are available.

01 / SENSE

Condition sensors

Measure selected parameters such as vibration or temperature on the test object.

02 / COLLECT

ESP32 acquisition

Read sensor outputs and transfer data to the processing application.

03 / PROCESS

Check readings

Apply basic data checks and compare readings with documented thresholds.

04 / DISPLAY

Dashboard

Show the latest readings, equipment status, and alert history.

05 / NOTIFY

Maintenance prompt

Flag abnormal readings so a responsible person can decide whether inspection is needed.

06 / FUTURE SCOPE

Validated prediction

Explore machine learning only if representative, labelled data can be obtained and evaluated.

Development status: MedSentry is currently in the research and planning stage. The literature survey is complete; hardware, dashboard implementation, and testing are planned work.
